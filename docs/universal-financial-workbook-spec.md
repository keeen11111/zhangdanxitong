# 规格草案：通用财务工作簿整合平台

> 状态：待业务确认。本文定义产品内核，不授权直接修改数据库 schema、公开 API 或会计计算规则。

## 1. 产品目标

建设一个面向多公司、多模板、多来源文件的通用财务工作簿整合系统。

每家公司都可以有不同的总表、Sheet 名、表头、列顺序、数据区块和更新文件。系统以工作簿内容和公司当次选择的总表为依据，不得把任何一个样本公司的文件名、Sheet 名、列位或业务规则写成通用处理的前提。

首期要解决的是“识别、映射、更新、审核和无损交付”的共性问题。工资、应收应付、报销、对账、费用、税务等均可作为业务主题；它们的专属计算口径和审批规则在后续以模块或配置形式扩展。

## 2. 目标用户与成功标准

| 用户 | 目标 |
| --- | --- |
| 财务人员 | 上传本公司的总表和来源更新表，获得可追溯、可复核的更新结果。 |
| 财务复核人员 | 查看系统不能唯一判断的事项，决定覆盖、保留、编辑或忽略。 |
| 平台管理员 | 管理公司隔离、模板映射配置和审计记录。 |

首期成功标准：

1. 两家公司使用不同 Sheet 名、表头和列顺序时，系统仍可建立工作簿画像并提出映射候选；不要求为第二家公司编写新的核心代码分支。
2. 一个来源字段只在目标主题、目标字段、记录标识和来源优先级均唯一时自动更新。
3. 无法唯一判断的内容进入独立人工处理队列，且可追溯到来源文件、Sheet、行号和原始值。
4. 导出的公司总表保留其原有的公式、格式、布局和非目标 Sheet。
5. 公司之间的文件、映射、人工决定和审计记录严格隔离。

## 3. 核心处理模型

```text
任意公司总表 + 任意公司来源表
  → 文件有效性检查与工作簿画像
  → Sheet / 表格区块 / 字段 / 标识候选识别
  → 目标总表主题与字段映射评分
  → 自动更新（仅唯一高置信度）或人工事项
  → 公式与格式完整性校验
  → 更新后的总表 + 独立人工处理清单 + 审计记录
```

### 3.1 与公司无关的中间模型

通用内核以以下结构处理数据，而不是直接以“员工”“工资”等某一业务实体作为唯一输入：

| 模型 | 含义 |
| --- | --- |
| `WorkbookProfile` | 文件级结构、工作表、日期/金额特征和来源元数据。 |
| `SheetProfile` | Sheet 的表头、数据区块、字段类型、样例、公式/样式特征。 |
| `TableRegion` | Sheet 内可处理的数据表区域及其标题、表头和行范围。 |
| `FieldCandidate` | 识别出的字段语义、数据类型、别名证据与置信度。 |
| `RecordIdentity` | 一条记录的稳定标识候选，例如单据号、客户/供应商编号、员工号、合同号或受控组合键。 |
| `MappingDecision` | 来源主题/字段/记录到目标位置的候选、分数、依据和最终决定。 |
| `ReviewTask` | 未能唯一确认的事项及人工处理结果。 |
| `ChangeAudit` | 自动或人工更新的来源、目标、旧值、新值、时间和操作者。 |

### 3.2 映射与自动化边界

- Sheet 名和文件名仅是弱提示；表头别名、数据类型、稳定标识、样例和表格结构是主要证据。
- 总表决定本次导出的 Sheet 结构、公式和格式；来源表不应因为名称不同而随意新增同主题 Sheet。
- 只有主题、字段、记录标识和来源优先级都唯一且达到高置信阈值时才自动写入。
- 未知主题、身份冲突、字段不唯一、重复值冲突或会破坏公式的写入必须停止自动处理，生成 `ReviewTask`。
- 通用内核不猜测会计分录、不编造金额、不把低置信度结果当成自动更新。

### 3.3 公司隔离与可配置性

- 每家公司（租户）拥有独立的文件、模板、映射别名、人工确认规则和审计记录。
- 人工确认可沉淀为该公司可解释、可禁用、可版本化的映射规则；不得跨公司直接复用。
- 新公司接入优先通过画像、映射配置和人工审核完成，不通过复制并修改某一公司的 Python 条件分支完成。

## 4. 首期范围

### 纳入

- Excel 工作簿的通用上传、画像、主题候选、字段候选、记录标识候选和目标映射。
- 多公司模板与来源表的租户隔离。
- 自动更新、独立人工审核、处理结果回导和完整审计。
- 公式、格式与非目标 Sheet 的无损保护。
- 以工资、应收应付、报销、对账、费用或税务样本验证通用内核，但不把任一类型固化为唯一结构。

### 不纳入首期

- 自动理解所有会计政策、凭证规则、税率、审批流和行业特定口径。
- PDF、扫描件、图片或非结构化合同的通用识别。
- 跨公司共享的映射记忆。
- 在没有明确字段与规则的情况下自动生成会计分录或金额。

## 5. 当前代码的适配差距

当前项目已有 Excel 无损导出、来源追溯、人工处理和部分语义识别基础；这些可被通用内核复用。

但当前仍存在薪资实体、特定来源类别和文件名嗅探等业务耦合。它们应被降级为“薪资领域适配器”或迁移配置，不能继续决定通用入口的行为。

## 6. 首期验收策略

| 验收场景 | 通过条件 |
| --- | --- |
| 公司 A 与公司 B 的结构差异 | Sheet 名、表头和列顺序不同，系统均能生成画像和候选，不因找不到固定名字而失败。 |
| 唯一映射 | 主题、字段、标识和优先级唯一时，正确更新 A/B 各自总表的对应位置。 |
| 不确定映射 | 多个候选或冲突时，不写入总表，生成带来源证据的人工事项。 |
| 模板完整性 | 更新后目标公式、样式和非目标 Sheet 的完整性检查通过。 |
| 租户隔离 | A 公司无法读取或使用 B 公司的文件、映射和审核决定。 |
