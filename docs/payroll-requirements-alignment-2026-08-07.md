# 药房工资自动化：需求与现有项目对齐

## 项目目标

以《子浩工作安排》为业务基线，建设一套确定性规则驱动的内部 Web 系统。财务人员一次上传工资主模板和多份来源表，点击“开始整合”后，系统依次完成数据解析、异动确认、最终库校验和 Excel 输出。

核心计算、字段匹配、异动识别、校验和写入均由 Python 规则完成，不使用 Agent 或大模型参与业务判断。无法唯一确认的数据必须进入人工处理或阻断导出。

## 已完成的真实数据验收

- 主模板：1 份；来源文件：2 份。
- 原始库：120 条实体记录；来源数据：163 条实体记录。
- 识别异动：入职 1、离职 2、调岗 2、考勤 39、社保 33。
- 最终库：194 条实体记录、40 名员工。
- 阻断项：0；提醒项：4。
- 已生成并复核包含 21 个工作表的工资 Excel。
- 新入职员工已插入总计行之前，工资字段、占比和汇总公式计算正确。
- Excel 重算后不存在 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?` 或 `#N/A` 公式错误。

## 当前标准流程

```text
上传并确认主模板与来源表
  → 加载原始数据库
  → 解析来源数据
  → 生成并确认异动
  → 构建最终数据库
  → 执行阻断/提醒校验
  → 按主模板导出 Excel
```

## 尚待产品化增强

以下事项不影响本轮真实数据闭环，但建议作为下一阶段工作：

1. 多模板同时上传时增加显式“设为主模板”操作，避免只按最新文件决定导出格式。
2. 建立同名、多候选、工号与身份证冲突的统一人工审核队列，并记录处理人和理由。
3. 将流水线会话、审核记录和导出审计从本地 JSON/SQLite 迁移到 PostgreSQL。
4. 增加项目月度快照、上月数据克隆、权限与操作审计。
5. 为来源表解析补充工作表、原始行号和命中规则的可追溯视图。

## 验收口径

财务人员可以一次上传全部文件，只点击一次“开始整合”，系统自动完成确定性处理；有阻断项时明确提示且不能导出，无阻断项时在 Web 页面提供可下载的、格式和公式完整的工资 Excel。Warning 是需要业务人员留意的数据提醒，不阻止输出。
