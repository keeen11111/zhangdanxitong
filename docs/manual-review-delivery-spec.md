# 规格：总表与人工处理文件分离

## 目标

财务人员完成整合后，在独立的“制作完成”页面查收两份文件：工资核算总表与待人工处理清单。总表保留全部来源工作表，但不再包含“待人工处理”工作表。

## 交付契约

- `POST /api/pipeline/{projectId}/integrate` 与 `GET /export/latest` 继续返回现有字段，并新增可选的 `issues_filename`。
- `GET /api/pipeline/{projectId}/export/issues/preview` 返回单独人工处理工作簿的首 20 行预览。
- `GET /api/pipeline/{projectId}/export/issues/download` 下载单独人工处理工作簿。
- 两个下载入口都校验当前来源文件指纹；来源变化后均拒绝下载旧结果。

## 用户流程

1. 首页上传并点击“开始整合”。
2. 整合完成后弹出确认窗口，点击“查看制作结果”进入 `/projects/{projectId}/result`。
3. 成果页可预览、重命名、保存总表；展开人工问题并预览、保存单独的人工处理表。
4. 保存优先使用浏览器的系统另存为窗口选择路径；不支持时使用标准下载。

## 验收标准

- 新生成的总表不包含“待人工处理”Sheet，且保留来源工作表。
- 单独人工处理工作簿包含序号、人员、问题、来源和处理状态列；无问题时仍可下载表头文件。
- 首页不再将完整结果堆在底部；完成后可通过弹窗进入成果页，且已有结果可从首页进入成果页。
- 成果页在窄屏和桌面均可访问两个预览与两个保存入口。

## 验证命令

- 后端：`python -m pytest -q`
- 前端：`npm run build`
