## 已可用的业务能力

- 用户登录、租户身份校验、项目和处理月份管理。
- 上传工资主模板及多份来源 Excel，识别并解析人员、薪资、考勤、社保公积金和个税数据。
- 六阶段核算主线：原始库、来源表、差异计算、审核、最终库、Excel 导出。
- 导出前执行 Blocker / Warning 校验；存在 Blocker 时拒绝导出。
- 保留工资模板的公式、格式和业务 Sheet；插入员工时扩展必要公式。
- 将总表与待人工处理清单分开导出；可将填写后的人工处理表回传并重新生成结果。
- 对部分同义 Sheet 与来源 Sheet 做语义判断，避免简单依赖文件名。

## 主要事实与限制

1. 当前默认数据库是 SQLite；PostgreSQL 仅是已记录的目标架构，不是当前交付能力。
2. 流水线会话、部分审核和导出元数据仍写入本地 JSON 文件，因此不适合多实例或高并发生产环境。
3. `backend/main.py` 仍同时注册 `modules`、`payroll`、`entities` 与 `pipeline` 路由；`pipeline` 尚未成为唯一业务入口。
4. `tasks/todo.md` 的旧勾选状态曾滞后于代码。现在的任务状态以本文件和更新后的任务台账为准。
5. 真实薪资文件、上传文件、数据库和导出文件必须保持在本地或获批准的内网环境，不能提交到仓库。

## 当前优先级

1. 确认 [通用财务工作簿整合平台规格](universal-financial-workbook-spec.md) 的首期边界，并将其转化为实施计划。
2. 将通用工作簿画像、映射、审核与导出内核置于工资等领域适配器之前；完成语义 Sheet 归并验收。
3. 确认前端技术路线：接受当前 Radix/Tailwind，或另立任务迁移到 Ant Design；两者不能同时作为标准。

5. 引入 PostgreSQL、Alembic、Docker Compose 和最低限度的 CI，形成可在内网部署的交付包。
