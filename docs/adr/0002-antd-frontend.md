# ADR-0002: 前端选用 Ant Design

- 状态: Accepted
- 日期: 2026-08-06
- 决策者: 项目团队

## 背景

前端源码缺失，阶段 3 需整体重写。初版 `package.json` 中依赖 Radix UI。需决定 UI 库。

候选方案：
1. **Radix UI**（保留原选型）：无样式底层组件，灵活但需自己写样式
2. **shadcn/ui**：基于 Radix 封装，自带样式，社区火
3. **Ant Design**：企业级中后台标准，组件丰富

## 决策

选用 **Ant Design**。

理由：
- 本系统是企业级内部管理系统（财务薪资核算），Ant Design 是该场景的标准选择
- 组件丰富（表格、表单、上传、步骤条），pipeline 6 模块工作台需要大量表格和数据网格
- 中文文档完善，团队上手快
- 开箱即用，样式一致，无需自己设计

## 后果

**好处**：
- 开发速度快，表格/表单/上传组件现成
- 企业级视觉一致
- 中文社区支持好

**代价**：
- 包体积较大（需按需引入优化）
- 与原 Radix UI 依赖不兼容，需清理 package.json 重新初始化
- 样式定制性不如 Radix（但本系统不需要高度定制）

**替代考虑**：若未来需要更灵活的视觉定制，可评估 shadcn/ui，但当前阶段 Ant Design 足够。
