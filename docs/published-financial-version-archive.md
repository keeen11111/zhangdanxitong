# 正式财务账单版本留档（第一版）

## 决策

正式账单不再直接使用“当前整合结果”文件。发布动作会先把 Excel 与发布元数据复制到项目独立归档目录，再把当前草稿标记为已发布。归档文件的 SHA-256 会被记录，并在每次下载前校验。

这是一种不改数据库、可立即运行的应用层版本留档方案，优先满足当前内部财库的可追溯需求。

## 发布后记录

每个正式版本记录：

- 版本 ID 与独立归档文件名；
- 原草稿文件名、自动更新数量和来源文件数量；
- 发布时的控制校验结果；
- 发布人 ID、姓名与发布时间；
- 归档 Excel 的 SHA-256。

重新上传文件或再次整合只会产生新的草稿；已经归档的正式版本不会随之更新。历史版本下载不再检查当前上传文件的输入签名。

## API

- `GET /api/financial-workbooks/{project_id}/integrations/published`：列出项目正式版本。
- `GET /api/financial-workbooks/{project_id}/integrations/published/{version_id}/download`：下载指定正式版本。
- 既有的 `.../latest/download` 在已发布时也会返回该次归档版本，而非可变的草稿文件。

## 安全边界

- 应用没有覆盖、编辑或删除正式版本的接口。
- 归档写入采用临时文件后原子替换；只有 Excel 复制与元数据写入成功后，草稿才会被标记为已发布。
- 下载前校验 SHA-256；归档文件被异常替换、损坏或元数据不一致时，系统拒绝下载。
- 此版本仍使用本地文件与 JSON 元数据。拥有服务器文件系统写入权限的人仍可同时改写文件与元数据，因此它不是密码学意义的不可篡改审计。

## 后续升级条件

在多用户、外部客户或合规审计场景启用前，需要迁移到数据库版本表、追加式审计事件、对象存储保留策略，以及独立的复核/审批身份。该升级会涉及数据库 schema，必须在实施前确认。
