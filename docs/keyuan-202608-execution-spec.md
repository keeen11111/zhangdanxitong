# Spec: 科园 2026.08 全量执行

## Objective

让已确认的科园月度任务可在独立草稿中完成，而不是在模型读取达到轮次上限后误报为“等待确认”。

本规格以当前运行 `fe890f5e24cd4ee4a9371af5c1599266` 已确认的 14 条计划为范围：草稿复制、OA 请款、交通通讯补贴、餐补、绩效奖金、业绩奖金、配送员值班费、考勤、防暑降温费、其他调差累计、台账、个税导出、静态页只读、待确认清单汇总。

## Safety Boundaries

- 原始总表与来源文件保持只读；所有写入只发生在独立草稿。
- 每项写入必须记录来源、目标单元格、旧值、新值及验证结果。
- 无来源、身份不唯一、表头不唯一、公式缓存缺失或范围不满足时，生成待确认项，不猜测或写入零值。
- 公式修改只允许经过明确的目标 Sheet、列、姓名或参数限制；保存后验证目标公式和非目标公式。
- 发布前必须通过计划覆盖、公式完整性、来源追溯及待确认项检查。

## Execution Contract

新增确定性步骤执行器，按已确认计划分阶段执行，不使用模型循环完成固定表格变更。模型只可用于提出映射建议，不能直接写入。

1. 准备草稿并记录输入哈希。
2. 执行结构和公式参数操作：OA 行复制/插入及月份更新、AU/AV 分母替换、防暑降温费参数更新。
3. 执行来源驱动的人员匹配操作：奖金、值班、考勤、社保公积金和个税。
4. 清空并重建“其他调差累计”的当月数据区，无法解析的条目写入待确认清单。
5. 生成待确认清单和覆盖/公式/追溯验证报告。

每阶段可恢复：已通过的阶段不会重复写入；失败阶段保存明确的错误代码、未完成步骤和下一步操作。运行到资源上限时状态为 `execution_incomplete`，前端显示“执行未完成”，不显示为用户确认。

## UI Contract

- 执行记录显示“执行记录 N 条”，不将工具调用和结果计为已完成业务动作。
- `MAX_TURNS_EXCEEDED` 显示为“模型读取达到本轮上限，尚未完成写入”，并提供继续执行的入口。
- 结果区明确显示：已完成业务步骤、未完成步骤、待确认条目、草稿验证状态和发布资格。

## Testing Strategy

- Python 单元测试覆盖每种工作簿变更、不可写保护、失败后可恢复和验证报告。
- API 测试覆盖运行状态、阶段续跑和发布闸门。
- TypeScript 单元测试覆盖执行记录标签与轮次耗尽提示。
- 浏览器验证覆盖“执行未完成”状态、继续入口和无控制台错误。

## Success Criteria

- 当前 14 条计划均有明确的执行器或明确的待确认输出，且不再由模型轮次决定是否完成。
- 当前草稿没有无来源的金额、没有未记录审计的写入，原件哈希不变。
- 工具日志不会被显示为已完成业务动作。
- 无法继续时页面展示具体原因和未完成步骤；通过验证前不能发布。

## Open Questions

- 已确认：`OA请款及审批` 本次目标工资月份为 **8月**。在第 8 行新增“8月”记录，原第 8 行“6月”记录下移并冻结为历史数值；新行保留工资汇总公式。
- “其他调差累计”的具体目标列映射和入离职缺勤规则必须从当前手册与来源表中解析并通过测试固化；证据不足时进入待确认清单。
