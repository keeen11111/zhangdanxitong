# 规格：通用语义 Sheet 归并与变更审核

## 目标

将外服账单系统从“依赖固定文件名、固定 Sheet 名”的处理方式升级为通用的工作簿整合能力。系统面向不同公司、不同结构的总表和变更表，对**每一张**来源 Sheet 与**每一张**总表 Sheet 建立画像并比较，通过表头、字段类型、样例数据及内容结构识别业务主题。

同一主题的来源 Sheet 即使名称不同（例如“人员异动”和“人员变更”），也应归并至总表已有的目标 Sheet；不得仅因名称不同新增业务 Sheet。该能力不以工资、社保、个税等既有实体为边界：未来未见过的新业务主题也使用同一套识别、映射与归并流程。无法可靠判断主题或字段映射的内容必须进入人工处理队列，不能自动写入总表。

## 已确认的业务规则

1. 总表是目标工作簿和 Sheet 结构的权威来源。
2. 来源 Sheet 与总表 Sheet 的匹配以内容语义为主，Sheet 名只作为弱提示。
3. 高置信度匹配到已有主题时，来源数据映射到该 Sheet，不新建同主题 Sheet。
4. 对可确定的业务数据，来源值直接覆盖总表中同一人员、同一字段的旧值。
5. 部门、岗位等组织或任职信息与其他业务字段遵循同一规则：人员、主题、字段和来源优先级均可唯一确定时直接覆盖。
6. 仅当无法确定人员身份、主题、字段含义、重复记录优先级或值冲突处理方式时，才进入待人工处理；不因字段类型本身扩大人工队列。
7. 每项自动或人工处理结果均保留来源文件、来源 Sheet、原始行号、目标 Sheet、匹配依据和处理结果，便于追溯。

## 处理流程

1. 对总表和所有来源工作簿的全部 Sheet 建立画像：表头、数据类型、样例值、候选业务主键、表格区块及公式/格式特征。
2. 为每个来源 Sheet 计算与总表各 Sheet 的主题匹配分数；只有唯一且达到高置信阈值的候选才自动归并。
3. 在已确定主题内，先推断可唯一定位记录的业务主键；人员表优先使用工号、身份证号和经验证的姓名组合，其他主题可使用项目编号、单据号、日期加类别等唯一键。无法推断唯一键时，使用完整行指纹作为辅助；仍不唯一才人工处理。
4. 将唯一高置信度的变更直接写入目标 Sheet；将身份、目标、字段或来源优先级不确定的变更生成独立人工处理任务。
5. 导出两份成果：更新后的总表，以及独立的待人工处理工作簿/页面。总表中不新增“待人工处理”Sheet。

## 人工处理事项

每条事项至少包含：公司/租户、处理月份、人员标识、字段、旧值、新值、来源文件、来源 Sheet、来源行号、候选目标、置信度、匹配说明、处理状态与处理人。

用户可选择：覆盖总表、保留总表、编辑后覆盖、忽略来源记录或将其指定到其他目标主题。确认结果应立即更新本次总表。

## 后续：公司级记忆

后续引入按公司（租户）隔离的“映射记忆库”，保存：

- 用户确认过的主题别名和字段映射；
- 用户确认过的人工处理规则；
- 每次应用规则的版本、时间与审计记录。

记忆只作为可解释的匹配证据和建议，不跨公司共享；低置信度或与既有规则冲突时仍进入人工处理。

## 成功标准

- 名称不同、内容同主题的 Sheet 被归并到同一目标 Sheet。
- 名称相似但内容不同的 Sheet 不会被错误合并。
- 部门、岗位等信息在匹配唯一时自动覆盖，在匹配不唯一时才进入人工处理。
- 可确定的业务数据能更新到目标总表。
- 每个未自动处理的项目都能由用户定位来源并完成确认。
- 新公司、新模板和未知 Sheet 可处理，不依赖工资实体、Sheet 名、文件名或为每个文件单独编写规则。

## 自动与人工的界限

自动处理必须同时满足：主题候选唯一且达到高置信度、人员标识唯一、目标字段唯一、同一优先级来源不存在互相矛盾的值。任一条件不满足，才创建人工事项。人工队列是异常兜底，不是固定字段的审批清单。
