# Implementation Plan: 智能且灵活的薪资更新

## Overview

在保留“身份冲突必须人工确认”的安全边界下，提升来源工作簿到总表的匹配率、规则可配置性和人工处理效率。

## Architecture Decisions

- 匹配采用可解释的多字段评分；工号/身份证号冲突永不自动写入。
- 默认阈值保持保守，只有唯一候选且达到阈值才自动合并；策略按租户和项目月份隔离。
- 规则和人工决定继续使用现有租户隔离的 JSON 存储，不引入数据库 schema 变更。
- 批量审核只允许对已有候选值或“保留总表”执行，服务端重新校验每个事项。

## Risks and Mitigations

| Risk | Impact | Mitigation |
| --- | --- | --- |
| 同名人员被错误合并 | High | 身份冲突硬阻断；仅唯一候选且上下文一致时自动匹配 |
| 规则配置过宽导致误写 | High | 服务端白名单字段、阈值下限和逐项审计 |
| 批量处理绕过单项校验 | High | 批量接口逐项检查 revision、候选值和权限 |
| 经验规则跨公司复用 | High | 所有规则按 tenant_id/project_id 隔离 |

## Open Questions
