# 实施计划：通用财务工作簿首期

> 依据 [通用财务工作簿整合平台规格](../docs/universal-financial-workbook-spec.md)。本计划不替代现有工资流水线；先新增一条独立的通用处理路径。

## 目标

让财务人员为任意公司创建项目，明确选择该公司的“待更新总表”与“来源更新文件”，并完成内容驱动的映射、人工事项生成和无损 Excel 下载。不要求总表包含“工资核算”Sheet，也不要求来源文件符合工资、社保或个税结构。

## 依赖图

```text
安全 Excel 上传与租户项目
        ↓
通用总表 / 来源文件角色
        ↓
工作簿画像与语义映射内核（已开始）
        ↓
通用整合 API 与结果元数据
        ↓
通用上传 / 预览 / 下载页面
        ↓
跨公司脱敏样本验收与可配置映射
```

## 任务

### U1：允许非工资总表作为通用财务总表

**状态：已完成（2026-08-24）。**

**范围：** 增加独立于 `template` 的通用总表文件角色；上传时只验证 Excel 安全性、项目归属和“每个通用整合批次仅一份总表”，不检查固定 Sheet 名。

**验收：**

- 不含“工资核算”Sheet 的费用、对账或应收应付总表可被选择为通用总表。
- 现有工资模板上传和工资流水线行为不变。
- 文件类型变更仍受项目/租户校验和现有大小、压缩包安全限制保护。

**验证：** `python -m pytest -q tests/test_generic_workbook_api.py`

**依赖：** 无。

**预估文件：** `backend/routers/projects.py`、`backend/schemas.py`、`tests/`。

### U2：通用整合 API（第一条完整服务路径）

**状态：已完成（2026-08-24）。**

**范围：** 新增一个只使用通用文件角色的整合端点，调用 `core.sheet_mapper.apply_semantic_sheet_updates`，保存本项目的结果文件和人工事项元数据，并提供下载/预览接口。

**验收：**

- 不依赖工资实体、人员识别或薪资月份即可完成费用类总表更新。
- 未匹配 Sheet、未知记录、重复主键、冲突值和公式目标均返回人工事项，不产生错误写入。
- 只能访问当前租户项目的输入与输出文件。

**验证：** 聚焦 API 测试与 `python -m pytest -q`。

**依赖：** U1。

**预估文件：** 新通用路由、`backend/main.py`、`backend/schemas.py`、`tests/test_generic_workbook_api.py`。

### U3：通用整合页面

**状态：已实现，待浏览器冒烟验证（2026-08-24）。**

**范围：** 为项目增加“通用财务整合”入口：选择总表、来源文件、发起整合、查看自动更新数和人工事项、下载结果。

**验收：**

- 页面不出现“工资核算”“员工”等作为必要操作条件。
- 用户能区分总表、来源文件、自动更新和待人工事项。
- 接口错误、上传中和无结果状态可理解且可恢复。

**验证：** `npm run lint`、`npm run build`，以及浏览器端一次人工冒烟验证。

**依赖：** U2。

**预估文件：** `frontend/src/lib/api.ts`、新增页面/组件、前端测试。

### U4：工作簿画像与映射解释

**范围：** 返回每个来源 Sheet 的候选目标、置信度、业务主键和未自动处理原因，供财务人员复核。

**验收：**

- 每个自动/人工决定均可说明来源 Sheet、目标 Sheet、行号和原因。
- 低置信度不会伪装为自动成功。

**验证：** 单元测试覆盖唯一、并列、未知主键、公式冲突和重复记录。

**依赖：** U2。

**预估文件：** `core/sheet_mapper.py`、通用 API、测试。

### 检查点：首期通用路径

- 一个没有工资 Sheet 的费用/对账总表能够经 Web 路径完成“上传 → 映射 → 人工事项 → 下载”。
- 现有工资流水线回归测试、前端 lint 和生产构建均通过。
- 跨公司脱敏样本到位后再开始 U5。

### U5：公司级映射配置与经验沉淀

**范围：** 在 PostgreSQL 迁移完成后，增加租户隔离、版本化、可审计的字段别名、主题映射和人工确认规则。

**验收：**

- 新公司可通过配置与人工确认接入，而非修改核心 Python 分支。
- 规则不跨租户泄露；低置信度仍不自动执行。

**依赖：** U1–U4、PostgreSQL / Alembic。

**状态：** 等跨公司脱敏样本与数据库迁移方案确认后实施。

## 风险与控制

| 风险 | 控制 |
| --- | --- |
| 误把行号/类别当业务主键 | 只允许明确稳定标识自动定位；其余进入人工事项。 |
| 总表公式或合计行被破坏 | 不自动插入未知记录，不覆盖公式；每次输出做公式完整性校验。 |
| 新公司结构差异导致硬编码回潮 | 新规则必须通过画像、配置和测试样本表达，不接受按公司名分支。 |
| 跨公司数据泄露 | 所有文件、结果、规则和审计按租户过滤与隔离。 |
